1. What I set out to make and for whom

I built a reproducible Python pipeline that turns a single contract file, storyboard.json, into a 60–90 second heritage short with Amharic narration, English subtitles, an instrumental score ducked under the voice, and dual exports (9:16 vertical and 16:9 horizontal reframe). The story is fictional: a young Ethiopian man tries many paths in the city, feels invisible and exhausted, and keeps moving when he remembers his promise to his mother.

Audience: young Ethiopians and diaspora viewers watching on phones—people in uncertain early careers, setbacks, and distance from family.

Intent: viewers should feel encouraged when progress feels slow or unseen, and moved by the quiet joy of keeping faith with family.

Look and sound: hand-painted gouache style (warm palette, stylized faces—not real likenesses); Gemini TTS in Amharic; Cloudflare FLUX for stills; FFmpeg for Ken Burns motion, assembly, ducking, and subtitles. Evidence: storyboard.json, docs/DESIGN.md, outputs/final/heritage_vertical.mp4.

2. What I learned from audience feedback

The brief asks for two rounds of testing (radio cut and near-final cut), each with at least three people from the intended audience, recorded in docs/DESIGN.md.

Radio cut (audio animatic): I produced per-shot Gemini TTS, combined narration with placeholder music, and listened for pacing before relying on expensive image generation. This confirmed that nine shots at roughly 6–8 seconds each fit the ~78 s runtime (nine shots plus a 4 s end card).

Near-final cut: Watching the vertical export on a phone and with headphones, I found that narration length did not always match estimated duration_seconds in the storyboard—Amharic TTS runs at a different pace than a words-per-second guess. Reviewers wanted the mother/smile beat to land clearly at the end; I kept shot reason fields explicit in the storyboard so each beat has a stated purpose.

3. Hardest problem and how I solved it

The hardest integration problem was Gemini text-to-speech. My first API payload used an invalid field (speechConfig), which returned 400 INVALID_ARGUMENT (logged in logs/runs.jsonl with model gemini-2.5-flash-preview-tts). I switched to the Interactions API with response_format audio and speech_config in providers/gemini_tts.py. After that, 45+ successful calls on gemini-3.8-flash-tts produced Amharic lines for all nine shots.

The hardest creative/technical problem was sync: picture length came from storyboard durations while voice length came from TTS. I added pad/trim in generators/audio/narration.py, but the durable fix is measuring each outputs/narration/sh_*.wav and updating duration_seconds, then re-running make videos and make assemble (documented in docs/FAILURES.md).

A close third was video without Wan GPU time: WanVideoProvider is not wired in code, so real-mode video uses Ken Burns on FLUX stills (KenBurnsVideoProvider). That met the deadline but some clips feel zoom-heavy; see docs/FAILURES.md (F07).

4. Suggested practices: one that helped, one that did not

Helped — storyboard as contract + caching: Keeping prompts, seeds, durations, and paths in storyboard.json, validated by JSON Schema before each run, made partial regeneration work. Fingerprints in core/cache.py mean changing one shot’s image_prompt can regenerate only that keyframe and downstream clip (see docs/EXPERIMENTS.md E08). This matched the assignment’s intent better than hard-coding prompts in Python.

Did not help as expected — reference sheet without image conditioning: I generated character/location references first (E05), but the Cloudflare FLUX wrapper is text-only: reference PNGs are not sent to the API. Continuity improved only through repeating style_block and character text, not through pixels. Next time I would use an img2img/edit endpoint or accept fewer characters (see E04, E05, docs/FAILURES.md).

Logging every model call to logs/runs.jsonl helped debugging and docs/COSTS.md (~88 calls, ~483 s API wall time, $0 on free tiers).

5. Ceiling work and insight

I stayed on the free stack: Cloudflare FLUX schnell, Gemini TTS, local FFmpeg. I did not wire HTTP clients for Wan 2.2 or ACE-Step in Python; instead I documented Ken Burns fallback and MUSIC_FILE override for an imported score. I ran more than ten logged experiments (docs/EXPERIMENTS.md), including Amharic TTS, FLUX look, ducking, cache selective regen, and end-card generation.

Insight: orchestration and measurement matter more than any single model—when TTS API shape changed, the pipeline survived because stages and logs were separate from providers.

6. What I would build next

  • Implement Wan TI2V (Kaggle notebook or WAN_API_URL) for hero shots only; keep Ken Burns for B-roll.
  • Wire ACE-Step or always document three music candidates with rationale in EXPERIMENTS.
  • Pass reference images into FLUX edit/img2img for character continuity.
  • Log seeds from storyboard.json into every model_call line.
  • Package the pipeline as a small CLI documented in README (make install, make film, per-stage make assemble, etc.) for graders cloning the repo.
